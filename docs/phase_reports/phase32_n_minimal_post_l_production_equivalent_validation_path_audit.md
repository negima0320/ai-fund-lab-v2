# Phase32-N — Minimal Post-L Production-Equivalent Validation Path Audit

## Executive Summary

Phase32-N is a read-only validation-path audit. I did not run fresh Historical validation, resume, replay, bootstrap, or mutate Runtime state. I inspected the existing runtime-test contract, command runner, reset/isolated-root code, Phase32-L prior-exit materialization code, and the Pre-L run:

`reports/runtime_tests/runs/runtime-test-historical-extended-smoke-20260825T235520054579Z`

Conclusion: the only currently valid production-equivalent path that can prove Phase32-L rematerialization and January Cash impact is a normal `fresh-run` from a clean reset state beginning at `2022-10-03` and running through `2024-01-31`. This is 327 business days in the prior run calendar. It is not the fastest semantic-only proof, but it is the minimum one-command path that satisfies materialization, re-entry semantics, capital, and Healthy-BULL Cash comparison without stale Pre-L state.

A cheaper 6BD slice, `2022-10-03` through `2022-10-11`, can prove the 83060 strict-prior PM EXIT bridge and non-GENERIC rematerialization if the run completes, but it cannot validate late-Plateau Cash impact or the `2024-01-31` positive-control capital context. Therefore it is useful as an optional developer confidence precheck, not as the Phase32-N recommended user validation command.

## Validation Requirements

Post-L validation must regenerate, under current code, from:

```text
strict-prior execution close
+
matching strict-prior PM decision reason evidence
```

into:

```text
prior_exit_reason
prior_exit_reason_codes
previous_exit_reason_class
```

Passing validation requires observing actual artifacts with:

- `prior_exit_reason_authority = STRICT_PRIOR_PM_DECISION_EVIDENCE`
- `previous_exit_reason_class != GENERIC`
- `semantic_buy_type = REENTRY`
- existing threshold/gate explanations for both pass and reject cases
- comparable target/requested/accepted/capital-competition evidence
- Healthy-BULL focus-day Cash, accepted NEW, selected REENTRY, and MCC winner comparisons

Return, final equity, and PnL are explicitly non-gates for Phase32-L acceptance.

## Recommended Path

Use the existing normal Runtime Test `fresh-run` command, not resume/replay/bootstrap. The recommended user command is a single production-equivalent narrow lifecycle run from `2022-10-03` through `2024-01-31`.
