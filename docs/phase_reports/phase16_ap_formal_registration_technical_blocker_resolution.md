## Candidate Result

Result:

```text
READY
classification: BUG
```

Evidence:

- `reports/phase16_formal_registration_preparation/candidate/row_count_resolution.json`

Root cause:

- Actual dataset parquet `split` column matches the Phase4-BF training summary.
- Dataset manifest/audit split stats were generated by date-range logic that excludes pre-`TRAIN_START` rows.
- Training uses `scripts/train_phase4bf_formal_candidate_model.py::split_dataset()`, which reads `dataset["split"]`.
- Dataset creation uses `assign_time_series_split()`, which maps all dates `<= TRAIN_END` to `train`.
- Manifest stats use `split_stats()` with a lower-bound `TRAIN_START`, so early train rows were omitted from the manifest/audit count.

Counts:

| Source | train | validation | test |
|---|---:|---:|---:|
| dataset manifest | 3,341,627 | 1,022,775 | 366,245 |
| training summary | 3,581,207 | 1,022,775 | 366,245 |
| parquet split column | 3,581,207 | 1,022,775 | 366,245 |

Delta:

```text
train_delta_training_minus_manifest: 239580
```

Formal interpretation:

- The model was trained on the actual dataset split column.
- The training summary is consistent with the physical dataset.
- The blocker is not a model/data mismatch; it is a manifest/audit split-stat bug.
