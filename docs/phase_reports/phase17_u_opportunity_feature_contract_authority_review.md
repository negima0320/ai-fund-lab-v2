## 1. Root Cause

Phase17-T closed the `opportunity_metrics_model_path_mismatch` as a path-string-only mismatch. Phase17-U confirms the next stop is a real schema authority conflict:

```text
buy_ai_reason=opportunity_feature_schema_mismatch
```

The accepted Opportunity Model and accepted Opportunity Training Metrics both require 32 `feature__*` inputs, including 16 market / sector context columns. The current Runtime Feature Producer generates only the Runtime v2 16-column Opportunity Feature Artifact surface, and the Consumer Readiness validator validates only that 16-column `runtime_v2_feature_contract_v1` surface.

This is why:

```text
Consumer readiness: READY
Opportunity inference: REVIEW_REQUIRED
```

Both judgments are internally consistent, but they are using different authorities.

## 7. 16-Column Authority

The 16 columns are required by:

- Accepted Opportunity Model payload
- Accepted Opportunity Metrics payload
- Accepted Opportunity feature schema member

They are not required by:

- `runtime_v2_feature_contract_v1`
- current Runtime Feature Producer output
- current Consumer Readiness validator

Classification:

```text
Case A: Runtime Feature Contract / Producer lacks columns required by accepted model.
Case D: Consumer Readiness Validator is incomplete relative to model input contract.
```

Not Case B: the accepted model is not merely old relative to metrics; model and metrics agree.  
Not Case C: metrics are not the only stale artifact; the model itself requires the same columns.

## 8. J-Quants Reproducibility

Market features are reproducible from J-Quants-derived daily quote features as of target date.

Sector features are reproducible from J-Quants-derived daily quote features plus listed issue sector mapping, but Phase5-P used a listed-master snapshot proxy. A production-grade Runtime path must establish PIT listed-sector authority before regeneration and acceptance.

No evidence was found that the 16 columns require Paper Ledger, Broker state, Current cash, Pending, Submit, Execution, PnL, backtest output, or forbidden future labels.

## 9. Retraining Need

Model retraining is not required if the project adopts the Phase5-P market / sector feature semantics into the common Runtime Feature Producer and regenerates / accepts Runtime Feature Artifacts under common authority.

Model retraining is required only if the project decides that the 16-column `runtime_v2_feature_contract_v1` remains the formal Opportunity Runtime input contract. In that case, the accepted 32-column Opportunity model is not compatible with current Runtime inputs.

## 10. Runtime Fix Sufficiency

A code-only Runtime producer patch is not sufficient by itself.

Required common closure:

1. Define market / sector columns in the common Feature Contract.
2. Connect market / sector enrichment to the Runtime Feature Producer.
3. Close PIT authority for listed sector mapping.
4. Update Consumer Readiness to validate selected Opportunity model input contract.
5. Regenerate Historical artifacts.
6. Promote / accept artifacts under the same Demo / Historical / Production authority.

## 11. Environment Impact

This is not Historical-specific.

The same accepted Opportunity model and Registry authority are used by Historical, Demo, and Production. Therefore the fix must be common. Historical-only defaults, null fills, dropped model columns, metrics rewriting, or consumer-only relaxation are prohibited.
