# Phase4-AR Candidate Output Audit Smoke

## Purpose

Phase4-AR audits the Candidate output generated by Phase4-AQ.

Phase4-AQ confirmed that the inference pipeline can load the smoke model and generate a top-50 candidate list. However, all candidate scores are identical. Phase4-AR records this as a model quality blocker while keeping the technical smoke pipeline result separate from model quality.

## Scope

Phase4-AR performs output audit only.

It checks:

- candidate artifact existence
- inference scores artifact existence
- candidate count
- scored count
- candidate rank validity
- candidate score distribution
- all-same-score problem
- candidate reason coverage
- feature snapshot and model version presence
- audit flags presence
- leakage / forbidden columns
- responsibility boundary
- absence of production promotion, backtest, trading, broker API, and order execution

Phase4-AR does not perform:

- model improvement
- feature addition
- label change
- retraining
- formal Candidate Quality Audit
- backtest
- trading
- Paper Trading
- Broker integration
- production promotion
- reader switch
- order execution

## Readiness Interpretation

Expected readiness for the current smoke output:

```text
TECHNICAL_PHASE4_SMOKE_COMPLETE_WITH_MODEL_QUALITY_BLOCKED
```

This means:

- schema is valid
- responsibility boundary is valid
- safety / leakage checks pass
- inference smoke pipeline is technically complete
- candidate score quality is blocked because ranking is ineffective

Only when candidate scores are not all identical and ranking is effective can this move to:

```text
READY_FOR_FORMAL_CANDIDATE_QUALITY_AUDIT
```

## All-same-score Problem

The current score distribution is expected to show:

```text
unique_candidate_score_count = 1
all_same_score = true
ranking_effective = false
```

This is not fixed in Phase4-AR. It is handed to Phase4-AS for root cause analysis.

## Responsibility Boundary

Candidate output is allowed to include:

- `candidate_score`
- `candidate_rank`
- `candidate_reason`
- `excluded_reason`
- `feature_snapshot_id`
- `model_version`
- `audit_flags`

Candidate output must not include:

- buy / sell / hold instruction
- allocation
- order
- execution
- PnL
- portfolio decision
- backtest or trade result
