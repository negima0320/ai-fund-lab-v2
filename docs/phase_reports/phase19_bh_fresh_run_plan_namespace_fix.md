# Phase19-BH — Fresh Run Plan run_id Namespace Error Fix

## Final Judgment

```text
PHASE19_BH_FRESH_RUN_PLAN_NAMESPACE_FIX_COMPLETE
```

`fresh-run` now constructs a complete Plan Namespace internally and validates the same request contract in dry-run and actual orchestration paths. Codex did not run an actual shared `.runtime` fresh-run; only dry-run and isolated automated tests were executed.

## Root Cause

The failed actual `fresh-run` reached the Plan step and called `plan_command(args, ...)` with the original `fresh-run` argparse Namespace. The `fresh-run` parser does not define `--run-id`, while `plan_command()` dereferenced `args.run_id`.

Failure evidence:

```text
reports/runtime_tests/fresh_runs/fresh-run-historical-smoke-20260721T011023225761Z/fresh_run_summary.json
```

Confirmed failure:

```text
failed_step = plan
error = 'Namespace' object has no attribute 'run_id'
run = NOT_EXECUTED
validate = NOT_EXECUTED
close = NOT_EXECUTED
```

Dry-run missed the issue because it called `build_plan()` directly instead of validating the `plan_command()` Namespace contract.

## run_id Ownership

Identifier ownership is explicit:

```text
fresh_run_id = one-command orchestration attempt
backup_id = pre-reset backup bundle
runtime_test run_id = Plan-owned Runtime Test identifier
```

The Runtime Test `run_id` is generated by Plan and then used by Run, Validate, Close, and run evidence paths. `fresh_run_id` and `backup_id` are not Runtime Test `run_id`.

## Implementation

Added:

```text
plan_namespace_from_fresh_run()
validate_plan_namespace()
```

`fresh-run` now uses the Plan Namespace helper for the actual Plan step:

```text
fresh-run args
-> plan_namespace_from_fresh_run
-> validate_plan_namespace
-> plan_command
-> generated Runtime Test run_id
-> run / validate / close
```

If Plan does not return a non-empty Runtime Test `run_id`, `fresh-run` stops before Run with `PRECONDITION_FAILURE`.
