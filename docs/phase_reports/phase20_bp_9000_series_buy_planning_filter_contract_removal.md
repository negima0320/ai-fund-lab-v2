This phase removes the Planning-stage 9000-series exclusion. It does not change Candidate AI, Opportunity AI, PM, Risk, Capital Allocation, thresholds, Accepted Generation, Broker code, or historical run results.

## Root Cause

Phase20-BN found that the Range run `runtime-test-historical-extended-smoke-20260724T030527368584Z` produced no trades. Five business days had:

```text
NO_SIGNAL:demo_capability_filtered_all_9000_series
```

Root cause:

```text
DEMO_BROKER_CAPABILITY_WORKAROUND_LEAKED_INTO_BUY_PLANNING
```

The 9000-series filter was not an Asset Universe exclusion. It was a Demo broker capability workaround applied before price, opportunity eligibility, listed-issue eligibility, and quantity sizing. That removed investment decisions before they could become submit-time broker outcomes.

## Original Design Intent

Phase14-E15 introduced the Morning AI / Planning / Pending connection. Its report explicitly states:

```text
Demoでは9000番台候補を除外する
```

It also states that Demo capability has `supports_9000_series_orders = false` and that Submit preflight blocks 9000-series orders.

`git blame` confirms the old Planning no-signal path came from the Phase14-era Morning Pipeline implementation around `src/ai_fund_lab_v2/runtime_v2/planning/morning_pipeline.py`.

## Contract Judgment

User-confirmed operating policy:

```text
9000番台銘柄は投資対象外ではない。
Demo環境で約定されないことがあるだけであり、投資判断から除外しない。
Production / Demo / Historical の売買判断は基本同一。
```

Judgment:

```text
9000-series exclusion is not an Asset Universe Contract.
It is a Broker execution capability concern.
Planning-stage uniform exclusion is contract-invalid.
```

No independent source was found that defines all 9000-series symbols as outside the investable universe.

## Affected Runtime Modes

The old filter was reached through common Morning Planning. Because Historical uses a runtime capability context too, the Planning-stage exclusion affected Historical evidence and produced Range no-trade days.

New responsibility split:

| Layer | 9000-series behavior |
|---|---|
| Candidate | Do not exclude only because symbol is 9000-series |
| Opportunity | Do not exclude only because symbol is 9000-series |
| BUY Planning | Do not exclude only because symbol is 9000-series |
| Pending | Preserve planned decision |
| Submit Guard | Broker capability may block Demo submit fail-closed |
| Broker result | Actual reject / unfilled / timeout / fill is execution evidence |

## Implementation Change

Changed:

- `src/ai_fund_lab_v2/runtime_v2/planning/morning_pipeline.py`
- `src/ai_fund_lab_v2/runtime_v2/planning/order_plan_builder.py`
- `tests/runtime_v2/test_phase14e15_morning_ai_planning_pending_connection.py`

In `morning_pipeline.py`, the call to `is_symbol_allowed_by_capability()` was removed from the candidate selection loop. The loop now proceeds directly from existing-position exclusion to price reliability, opportunity BUY eligibility, listed-issue BUY eligibility, and quantity sizing.

The old no-signal reason:

```text
NO_SIGNAL:demo_capability_filtered_all_9000_series
```

is no longer generated by new Planning evidence. Existing evidence remains readable because the string is not removed from historical reports.

In `order_plan_builder.py`, the capability-aware helper no longer filters investment decisions. It delegates to the ordinary order-plan conversion and documents that broker capability is enforced by Submit Guard.

## Production / Demo / Historical Consistency

The implementation does not add a Historical-only allow path and does not add Demo-only AI behavior. Production, Demo, and Historical now share the same Planning treatment for 9000-series symbols.

Preserved checks:

- price reliability
- budget / lot quantity sizing
- existing-position exclusion
- Opportunity BUY eligibility
- listed-issue BUY eligibility
- safety authority
- capital deployment policy
