## Same-Day Morning Retry Identity Fix

Before the successful E20 retry attempt, the first E20 submit attempt was blocked before Broker submit:

- `submitted_count=0`
- `blocked_count=5`
- reason: `duplicate submit guard or pending lifecycle blocked`

Root cause: Morning generated a new Pending file but reused the same deterministic `order_plan_id` / `pending_plan_id` / `pending_item_id` pattern for the same business date and same selected symbols. The duplicate guard correctly rejected it because E17 had already recorded that plan identity in the orders ledger.

Fix applied as normal operation behavior, not a recovery-only path:

- Morning planning now generates a per-run `planning_run_id`.
- `AIPlanningSignal.signal_id` includes that run id.
- `OrderPlanItem.order_plan_item_id`, `OrderPlan.order_plan_id`, and `PendingOrderPlan.pending_plan_id` become unique per Morning run.
- Existing duplicate-submit protections remain intact.
